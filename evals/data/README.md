# Evaluation dataset

## Files

| File | What it is | Written by |
|---|---|---|
| `topics.json` | 20 topics, each with four question forms in English and Portuguese | hand written |
| `pairs.jsonl` | 220 labelled pairs, one json object per line | generated by `scripts/build_dataset.py` |
| `similarities.json` | the same 220 pairs with the cosine the gateway's runtime measured | generated by `scripts/score_pairs.mjs` |

`pairs.jsonl` is generated but versioned. It is the thing every downstream
number is computed from, so a change to it has to show up in a diff. It is
one object per line and sorted by construction, so a topic edit moves a handful
of adjacent lines rather than reflowing the file.

## How the pairs were built

Each of the 20 topics carries four question forms per language:

- **base** — the question
- **paraphrase** — the same question in different words, which the cache *should* collapse
- **sibling** — a different question about the same subject, which it should not
- **minimal** — the base with a small edit that changes the answer

The five labelled categories come from combining those forms. The combination
rules live in `scripts/build_dataset.py` rather than in the data, so the pairing
logic is reviewable as code instead of buried in 220 hand made judgement calls.

| Category | Built from | Should hit | n |
|---|---|---|---|
| `paraphrase` | base ↔ paraphrase, same language | **yes** | 40 |
| `same_topic` | base ↔ sibling, same language | no | 40 |
| `minimal_pair` | base ↔ minimal, same language | no | 40 |
| `cross_lingual` | English ↔ Portuguese, same question | no | 40 |
| `unrelated` | base of one topic ↔ base of another | no | 60 |

`paraphrase` is the only category labelled should-hit. Every other one is a
wrong answer if the cache returns it.

The `unrelated` controls pair topic *i* with topic *i+7*, an offset coprime with
20 so every topic appears exactly twice and none is paired with itself. 40 are
same-language and 20 cross both languages. That split is deliberate: comparing
those two groups measures whether the embedding encodes language at all,
independent of topic, which is the first question etapa 3 has to answer.

The `minimal_pair` category is split across three kinds of edit, recorded in the
`note` field:

- **entity** (20) — one noun swapped for a neighbour: *coffee leaf rust* → *coffee berry borer*
- **negation** (12) — the claim reversed: *carry load through its main cables* → *without using its main cables*
- **temporal** (8) — the scope moved: *in the 1960s* → *in the 2010s*

## Volume, and why this much

220 pairs, 40 to 60 per category.

The number was chosen against what a threshold sweep needs to resolve. ADR 0001
recorded a separating band of 0.0017 between paraphrase and translation. At 40
pairs per category, one mislabelled pair moves precision or recall by about 2.5
points, which is visible in a chart without dominating it. At 10 it would swing
the result; at 500 no human would read every line, and the labels would stop
being trustworthy exactly where trust matters most.

The ceiling is reading, not compute. Scoring all 220 pairs takes under 8 seconds.
The binding cost is that every pair was written and can be re-read by a person,
and 220 is near the limit of what one sitting sustains.

## Bias, stated plainly

**The pairs were written by the same person building the thing being measured,
after having already seen how the model behaves.** That is the dataset's largest
weakness and it does not have a fix inside this week's scope.

Concretely:

- **The expected answer was known while writing.** ADR 0001 already recorded that
  cross-language pairs land near same-language paraphrases. The cross-lingual
  pairs were written by someone expecting that, and a paraphrase written to be
  "clearly a paraphrase" is an easier case than one drawn from real traffic.
- **The minimal pairs were written to be hard.** They are adversarial by
  construction. They show what the embedding *can* miss, not how often it misses
  in practice. Nothing here estimates how frequently a real user sends a negated
  variant of a cached question.
- **Topics were chosen for being separable.** Twenty subjects with little
  overlap make the `unrelated` controls clean, which flatters the low end of the
  distribution. Real traffic to one gateway is far more clustered.
- **Both languages were written by one author, and English is not their first
  language.** The Portuguese is native and idiomatic; the English is fluent but
  written by the same hand rather than sampled from English speakers. A
  systematic register difference between the two halves cannot be ruled out, and
  it would land directly on the cross-lingual comparison.
- **There is no second annotator.** No label was reviewed by anyone else, so
  disagreement over what counts as a paraphrase is invisible here. There is no
  inter-annotator agreement figure because there is only one annotator.

What this dataset can support is a statement about **whether a threshold exists
that separates these categories**. A finding that no threshold separates two
categories is robust to the bias above: if pairs written to be easy still cannot
be separated, harder ones will not do better.

What it cannot support is any statement about **rates in production** — hit rate,
how often a false positive would occur, or savings. Those need traffic, and the
traffic this project has is k6-generated. That limitation is carried into
etapa 4 rather than papered over.

## Reproducing

```
uv run python scripts/build_dataset.py     # topics.json -> pairs.jsonl
pnpm build && node scripts/score_pairs.mjs # pairs.jsonl -> similarities.json
```

The scoring step needs Node. Python never loads the model, and the environment
is built so it cannot: `onnxruntime` is not an installed dependency. ADR 0007 is
the reason.

Every results file carries a provenance block naming the model, quantisation,
runtime versions, graph optimisation level and a sha256 of the dataset it scored.
`load_results` refuses a file whose digest does not match `pairs.jsonl` on disk,
so an analysis cannot silently run against numbers from an older dataset.
